# 后续任务

更新日期：2026-11-16（Asia/Shanghai）

当前基线：**0.1.0**。本文是后续工作清单，不代表这些问题均已复现为故障。源码现状和验证记录见 [开发进度](DEVELOPMENT_PROGRESS.md)。

## P0：优先完成真实接入验收与边界处理

### 1. 在真实 DSH 桌面 profile 安装验收

- [ ] 构建并安装本地 tarball，确认设置页、样式和 Host 路由均加载。
- [ ] 验证桌面 IPC Fetch 通道、主题切换、重启 DSH 后配置与来源记录恢复。
- [ ] 分别走通 stdio 与 Streamable HTTP 的测试、保存、启停、重启、删除。
- [ ] 验证实际 DSH 凭证引用：存在、缺失、更新后重连、凭证服务不可用。
- [ ] 验证官方 Manager 中已有服务、插件注册服务及继承配置的可操作边界。

验收标准：记录实际 DSH 版本、运行平台和结果；正式实例工具可用于会话，停用和删除后撤回工具；无重复服务或工具注册。日常 profile 的安装和已有服务变更应由维护者选择执行时机。

### 2. 实际来源应用配置兼容矩阵

- [ ] 为四个来源补充脱敏的真实配置样本及来源版本，继续使用独立临时文件测试。
- [ ] 覆盖 Codex 的 `CODEX_HOME`、env 请求头、Bearer 环境引用；OpenCode 的 JSONC、新旧容器和路径覆盖。
- [ ] 覆盖重复配置、同名不同配置、相同 URL 不同认证、禁用项和未知字段。
- [ ] 验证相对命令、相对参数、工作目录、GUI PATH 与终端环境不同的场景。

验收标准：已支持字段不丢失；无法迁移的字段明确提示；来源文件不被写入；不同身份不会被自动合并。

### 3. 统一保存等待与启动超时

- [ ] 检查 `src/host/config.js` 的超时校验上限与官方 Manager 可接受范围。
- [ ] 将 `src/host/service.js` 的正式连接等待预算与 `startupTimeoutMs` 协调，避免启动较慢时被固定等待时间提前判失败。
- [ ] 覆盖首次 npx 下载、慢网络、重连退避、工具发现较慢和清理失败。

验收标准：超时设置有一致含义；验证失败有明确阶段和诊断；不报告旧实例连接成功，不遗留未经确认的测试进程。

### 4. 停用保存与失败诊断保留

- [ ] 核对缺失环境引用能否作为停用配置保存：当前部分路径会把未解析模板交给官方校验，不能假定停用就能接受不完整配置。
- [ ] 为不能保存的字段提供明确反馈；如需草稿，单独设计草稿存储，不伪装成 Manager 已接受的配置。
- [ ] 检查失败后自动停用是否会使服务行丢失最近的失败原因；需要时保存脱敏的最近诊断。
- [ ] 核对删除后连接清理期间的行状态及来源重新添加时机。

验收标准：明确区分未保存、停用已保存、正式连接失败；重新打开详情仍能找到必要的失败原因；诊断记录不含密钥明文。

### 5. 自动化端到端与可重复验证

- [ ] 将已有浏览器人工 / 工具验收转为可重复运行的端到端用例。
- [ ] 覆盖 JSON 粘贴后立即测试、切换表单、多服务选择、手动更名、env 补全、隐藏值改名、保存后关闭和失败保留。
- [ ] 覆盖删除后重新导入、外部配置变更、连续操作以及测试期间关闭 / 卸载。
- [ ] 使用受控本地 MCP 和临时目录，避免测试依赖 npx 在线下载、真实账户或用户配置。
- [ ] 接入 CI：单元测试、语法检查、构建、真实集成测试和打包内容检查。

验收标准：干净检出后按文档即可复现；失败有可定位输出；不需要开发机现存的 `/tmp` 或 profile 数据。

## P1：补齐管理体验

| 任务 | 验收重点 |
| --- | --- |
| 项目级扫描与配置归属 | 只扫描当前或用户选择的项目；显示来源范围；不遍历整盘；明确最终保存范围 |
| 配置导出、备份与恢复 | 默认不导出密钥；恢复前预览冲突；来源信息与连接配置分开 |
| 未保存内容保护 | 关闭编辑窗口、切换页面时避免丢失用户修改；读取隐藏值本身不算用户编辑 |
| 测试取消与更清晰的阶段进度 | 用户可停止等待；取消后关闭连接；不能误显示保存成功 |
| 表单错误与冲突处理 | 尽量定位到字段；revision 冲突能核对最新值，避免反复提交旧 revision |
| 运行环境帮助 | 命令绝对路径、PATH、目录、变量引用与凭证引用的差异可直接理解 |
| 来源缓存与状态刷新 | 明确手动文件候选保留范围；窗口重开、外部修改及并发刷新不显示旧状态 |
| 可访问性与布局 | 键盘焦点、模态背景交互、长参数、窄窗口、深浅色主题、中文溢出 |
| 跨平台验证 | 优先补充 Windows 的可执行命令、PATH / PATHEXT、目录和安装行为验证；再覆盖 Linux |
| 多语言 | 中文 / 英文跟随 DSH 语言设置，避免业务组件中继续散落文本 |

### 完整 OAuth 与凭据管理

- [ ] 先确认目标 DSH 版本的官方授权能力，优先复用其凭证和生命周期接口。

- [ ] 对其他应用私有凭据明确提示重新授权；不假定复制配置等于复制登录状态。

### 工具权限与调用测试

- [ ] 确认官方服务提供可执行的单工具权限接口后，再设计每工具开关。
- [ ] 如增加手动工具调用，提供参数校验，沿用 DSH 的审批与执行机制。
- [ ] 不通过隐蔽调用业务工具来判断服务是否可用。

## 提交与发布约定

- 本次提交统一使用 `0.1.0`；不把之前的本地临时编号写成正式发布历史，不自动创建 tag、推送或发布 npm。
- 版本号以 `package.json` 和 `package-lock.json` 为准；安装示例、进度文档随正式版本同步。
- Git 提交源码、测试、锁文件和文档；忽略 `node_modules/`、`lib/`、`dist/`、本地 tarball、日志和环境文件。
- 交付前运行适用检查，更新开发进度与待办状态；未验收的项目不能标为完成。
- 真正发布时，从干净检出构建并打包；确认 tarball 包含 Host、共享模块、浏览器模块、样式和 bundle patch，再安装验收。
