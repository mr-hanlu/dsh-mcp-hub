## 建议阅读顺序

1. 新用户：README → 使用说明；
2. 接手的开发者：README → 开发进度（最近一轮）→ 后续任务 → 测试说明；
3. 做认证 / OAuth：开发计划 → 使用说明的 OAuth 章节 → 后续任务；
4. 准备发版：测试说明的“建议的验证顺序” → 桌面实例验收清单。

## 维护约定

- 日期统一用 `YYYY-MM-DD`（Asia/Shanghai）；
- 测试计数、e2e 步数、打包文件数只写实测值，并注明验证版本（当前 DSH `0.2.2-rc.5`）；
- 每轮结束更新“开发进度”的收工状态与对应章节，并把“后续任务”里完成的项打勾；
- 计划类文档（`DEVELOPMENT_PLAN_*`）保留当时的判断，不追改结论，只在顶部标注快照；
- 复审报告含内部讨论，不随 npm 包发布（`package.json` 的 `files` 已排除 `docs/CODE_REVIEW*`）。
